# Принятые решения

Решения зафиксированы по итогам обсуждения требований 17.11.2026. Менять их можно только осознанно, обновив этот файл и `docs/plan.md`.

| № | Решение | Причина |
|---|---------|---------|
| 1 | Только фронтенд: HTML, CSS, чистый JS, без сборки и зависимостей | Учебное задание без требований к стеку; так проще сделать, показать и защитить |
| 2 | Данные в `localStorage`, без сервера и регистрации | Не нужны аккаунты и сеть; данные сохраняются между перезагрузками |
| 3 | Сайт работает через `file://`, без ES-модулей | Открывается двойным кликом, не нужен локальный сервер и установка пакетов |
| 4 | Ввод трат вручную; демо-данные одной кнопкой | Чтобы сразу было что анализировать на защите |
| 5 | Отчёты: сводка, категории, график, сравнение с прошлым периодом | Достаточно для формулировки «анализировать траты за разные периоды», не перегружает проект |
| 6 | Периоды: неделя, месяц, год, свой диапазон | Закрывает требование «разные периоды» без лишней логики |
| 7 | Светлая и тёмная темы с запоминанием выбора | Пользователь захотел переключатель тем; реализуется на CSS-переменных |
| 8 | Графики — свой SVG, без Chart.js | Работает офлайн, нет сторонних файлов и зависимостей |
| 9 | Рубли, фиксированный список из 8 категорий | Проще форма, расчёты и интерпретация отчётов |
| 10 | Только траты: без доходов и лимитов бюджета | Ближе к заданию; меньше объём и меньше мест для ошибок |
| 11 | Суммы хранятся в копейках целым числом | Исключает ошибки округления при сложении |
| 12 | CSV-импорт отложен на будущее | Пользователь выбрал ручной ввод для первой версии; модель данных уже совместима |

## Отложено, но учтено в архитектуре

- **CSV-импорт выписки.** Добавляется методом `importRows()` в `js/store.js` и отдельным разбором файла; экраны и аналитика не меняются.
- **Свои категории.** Если понадобятся, достаточно расширить `CATEGORIES` и форму, но это меняет формат отчётов — потребуется обновление плана.
- **Бюджетные лимиты и доходы.** Отдельная функциональность, в текущую область не входит.
