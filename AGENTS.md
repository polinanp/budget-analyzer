# Правила работы над проектом

Документ для ИИ-агентов и для себя: что можно делать в этом репозитории, а что нельзя. Решения зафиксированы, менять их можно только осознанно и с обновлением документации.

## Что это за проект

Учебный одностраничный сайт «Анализ трат»: ручной учёт расходов, отчёты за периоды, графики, две темы. Подробности — в `docs/plan.md`.

## Жёсткие технические ограничения

1. Только HTML, CSS и чистый JavaScript. Никаких фреймворков, транспиляторов, сборщиков, CSS-препроцессоров и пакетов из npm.
2. Сайт обязан работать при открытии `index.html` напрямую через `file://`, без локального сервера.
3. Поэтому нельзя использовать ES-модули (`type="module"`), `fetch` к локальным файлам и любые импорты. Скрипты подключаются обычными `<script defer>` в порядке: `store.js`, `periods.js`, `charts.js`, `app.js`.
4. Никаких внешних ресурсов: без CDN, шрифтов из интернета, Chart.js и других библиотек. Графики рисуются своим SVG-кодом. Сайт должен полностью работать офлайн.
5. Данные хранятся только в `localStorage` браузера. Сервера, базы данных, авторизации и сетевых запросов нет.
6. Интерфейс и все сообщения — на русском языке.
7. Суммы хранятся в копейках целым числом (`amountKopecks`), валюта — рубли. Не переходить на числа с плавающей точкой в рублях.
8. Категории фиксированные: `food`, `transport`, `housing`, `fun`, `health`, `clothes`, `subs`, `other`. Не добавлять произвольные категории без изменения плана.

## Ключи localStorage

- `budget.transactions.v1` — массив трат.
- `budget.theme` — `"light"` или `"dark"`.

Формат записи траты:

```js
{ id: "uuid", amountKopecks: 45250, category: "food", date: "2026-11-17", note: "Обед" }
```

Менять формат данных или ключи можно только вместе с обновлением `docs/plan.md` и `docs/decisions.md`.

## Структура файлов

- `index.html` — разметка страницы и подключение ресурсов.
- `css/styles.css` — все стили и токены тем.
- `js/store.js` — категории, чтение/запись localStorage, CRUD, демо-данные.
- `js/periods.js` — границы периодов, предыдущий период, агрегация, сравнение.
- `js/charts.js` — SVG-графики и форматирование чисел.
- `js/app.js` — состояние, рендер, обработчики, валидация, темы.

Не добавлять новые файлы без необходимости. Не создавать `package.json`.

## Стиль кода

- `"use strict"`, `const`/`let`, строгое сравнение `===`, точки с запятой.
- Каждый файл оборачивается в IIFE и выставляет наружу только нужные функции, без глобального мусора. Общий неймспейс — `window.Budget`.
- Имена: `camelCase` для переменных и функций, `UPPER_SNAKE_CASE` для констант.
- Пользовательские строки (комментарии к тратам, суммы) выводить через `textContent`/`createElement`, не вставлять в `innerHTML`. Разметку через `innerHTML` — только для статических фрагментов без данных пользователя.
- Все даты — строки `YYYY-MM-DD`, сравнение строковое, без объектов `Date` для хранения.
- Никаких `console.log` в финальном коде, кроме осознанной отладки.

## Доступность и качество интерфейса

- У интерактивных элементов есть подписи; у кнопки темы — `aria-pressed`.
- Форма показывает ошибки текстом рядом с полем, а не только через `alert`.
- Оба цветовых варианта должны оставаться читаемыми: текст на фоне — достаточный контраст.
- Вёрстка проверяется на ширине 360px и 1440px.
- Пустые состояния и крайние случаи (одна категория, большие суммы, нет данных) не должны ломать графики.

## Как проверять

Автоматических тестов и сборки нет. Проверка — ручная:

1. Открыть `index.html` двойным кликом в браузере.
2. Пройти чек-лист из `docs/plan.md` (раздел «Проверка»).
3. Убедиться, что в консоли нет ошибок, а данные сохраняются после перезагрузки.

## Документация обязательна

- Перед началом этапа свериться с `docs/plan.md`.
- После завершения этапа: добавить запись в `docs/journal.md`, отметить пункт в таблице этапов `README.md`, при заметных изменениях — запись в `CHANGELOG.md`.
- Новое решение по ходу работы — строка в `docs/decisions.md` с причиной.

## Чего не делать

- Не добавлять бэкенд, базу данных, вход в аккаунт, синхронизацию и сетевые запросы.
- Не добавлять доходы, лимиты бюджета и мультивалютность: это вне области первой версии.
- Не реализовывать CSV-импорт сейчас. Архитектура должна позволять добавить его позже без переделки экранов.
- Не менять согласованные решения молча: сначала обновить документацию, потом код.
